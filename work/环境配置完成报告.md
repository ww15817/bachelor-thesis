## 3. 与清单不一致的地方（必须说明）

### 3.1 附录 A 的 Poisson 脚本改了 3 行

dolfinx 0.11 的 `LinearProblem` 新增了**必填**关键字参数 `petsc_options_prefix`，
清单里的原脚本会直接抛 `TypeError: __init__() missing 1 required keyword-only argument`。
改动只有：

```python
prob = LinearProblem(
    a, L, bcs=[bc],
    petsc_options_prefix=f"poisson_{n}",      # ← 新增
    petsc_options={"ksp_type": "preonly", "pc_type": "lu"},
)
```

物理设置、网格、边界条件、判据都没动，峰值也与清单的 `0.0736 ± 3%` 吻合。
脚本存于 `~/poisson_check.py`。

### 3.2 `openEMS --version` 的正确读法

`--version` 不是 openEMS 认识的选项（会跟一句 `unrecognised option '--version'`），
但**版本横幅在解析参数之前就打印了**，所以判据看横幅那行即可：

```
 | openEMS 64bit -- version v0.37.0-40-g5fecbb5
```

`v0.37.0-40-g5fecbb5` 表示「v0.37.0 之后第 40 个提交，短哈希 5fecbb5」——即**高于 v0.37.0**。

### 3.3 gmsh

conda-forge 的 `gmsh` 包只装可执行文件，Python 模块在 `python-gmsh` 包里。
已补装：`gmsh 4.15.2` 可 `import`。

## 4. 踩到的坑与处理（下次换机器会再遇到）

### 4.1 apt 下载的 deb 损坏

`proj-data` / `libgdal30` 解包报 `ZSTD_decompressStream error : Corrupted block detected`。
→ `apt-get clean` + 重下这两个包 + `apt-get install -f` 后补齐，最终 12 个依赖全 OK。

### 4.2 子模块克隆卡死（gh-proxy 挂住连接）

一次性 `git submodule update` 会让 openEMS 子模块停在 3 MB 不再动。
原因是脚本里 `http.lowSpeedLimit=0`——**永不超时**。
→ 改成逐个拉、带 `lowSpeedLimit=30000 / lowSpeedTime=45` 的**低速即断**策略，
断了就清理重试。7 个子模块全部检出（CSXCAD 261 / openEMS 609 文件）。

### 4.3 Windows 的 Anaconda 污染 Linux 编译（最隐蔽的一条）

第一次编译在 CSXCAD 阶段失败：

```
/mnt/d/Anaconda/Library/include/H5public.h:247:19: error:
  conflicting declaration 'typedef long long int ssize_t'
```

根因：**WSL 默认把 Windows 的 PATH 追加进 Linux 的 PATH**，里面有
`/mnt/d/Anaconda/Library/bin`，于是 CMake 的 `find_package(HDF5)` 选中了 **Windows 版 HDF5 1.12.1**
（系统的是 1.10.7），头文件自然对不上。

对照实验确认（同一份 CMakeLists）：

| 环境 | HDF5 版本 | 头文件 |
|---|---|---|
| 含 Windows PATH | 1.12.1 | `/mnt/d/Anaconda/Library/include` |
| 净化 PATH | 1.10.7 | `/usr/include/hdf5/serial` |

→ 编译时用 `env -i` 把 PATH 收敛成 `/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin`，
问题消失。**以后在 WSL 里编任何 CMake 工程都建议这样做。**

### 4.4 清华 PyPI 在这条线路上 403

Python 扩展构建时 `pip install setuptools cython` 报 `from versions: none`。
实测：`pypi.tuna.tsinghua.edu.cn` → **403**，`mirrors.aliyun.com/pypi/simple` → 200。
（注意：清华的 **conda-forge** 镜像是通的，只有 PyPI 那个 403。）
→ pip 改走阿里云，扩展构建通过。

### 4.5 `bash -lc` 里找不到 conda（清单 5.4 的加强版）

`conda init bash` 把钩子追加到 `~/.bashrc` **末尾**，而 Ubuntu 的 `.bashrc` 开头有
「非交互就 return」的判断，所以 `bash -lc "conda activate fenicsx"` 永远走不到那一段。
→ 把 conda 钩子与 openEMS 的 `PATH/LD_LIBRARY_PATH` 也写进 `~/.profile`
（登录 shell 会读，且不受交互判断影响），并用幂等标记块包裹。两种 shell 都正常。

### 4.6 浅克隆导致版本号变成裸哈希

首版 `--depth 1` 克隆没有 tag，CMake 的 `git describe --tags --always` 只能回落成 `5fecbb5`。
→ 给 openEMS 子模块补了 tag 与历史（`fetch --tags` + `--deepen=200`），
`describe` 变为 `v0.37.0-40-g5fecbb5`，重编后横幅显示真实版本。
