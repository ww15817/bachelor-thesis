## 0. 背景与目标

本科毕业设计《天线仿真开源软件集成与应用》的仿真环境。

链路分两段：射频段用 **openEMS**（FDTD 全波）算馈源，结构段用 **FEniCSx**（有限元）算反射面变形，
中间的自研射线追踪 / 物理光学积分用 **Python** 科学计算栈自己算。

**关键约束：FEniCSx 不能在原生 Windows 上跑。**

- `petsc4py` 在 conda-forge 的 win-64 上不存在，PyPI 也没有 Windows 轮子；
- ffcx 做表单 JIT 时在 Windows 上只认 MSVC（`cl.exe`）。

openEMS 同理，Linux 下编译最省事。所以目标结构是：

```
Windows 侧：Python 虚拟环境 → 跑自研 GO/PO 代码（纯 numpy，不需要 Linux）
WSL 侧：    Ubuntu 22.04 → openEMS v0.37 + FEniCSx dolfinx 0.11
```

**一句话验收：在 WSL 里能跑一次 openEMS 的真算例、能跑一次 dolfinx 的真求解；在 Windows 里能跑通项目自带的 33 条测试和整条流水线，且数字与文档里的一致。**

## 4. 已知坑（v1 已有，按发生概率排序）

### 4.1 子模块「假完成」

**现象**：`git submodule status` 显示所有子模块都在正确 commit，但目录里只有一个 `.git`，源码没检出。

**原因**：克隆中断留下的残状态，`git submodule update` 认为已完成而跳过。

```bash
cd ~/openems-src
git submodule update --init --recursive --force --checkout

# 若仍为空，逐个恢复
for d in CSXCAD AppCSXCAD QCSXCAD CTB fparser hyp2mat openEMS; do
  n=$(ls -A "$d" 2>/dev/null | wc -l)
  [ "$n" -le 1 ] && git -C "$d" checkout -f
done
```

**判据**：`CSXCAD/CMakeLists.txt`、`openEMS/CMakeLists.txt`、`AppCSXCAD/CMakeLists.txt` 三个都存在。

### 4.2 编译在 QCSXCAD 阶段失败

**报错**：`QVTKOpenGLStereoWidget.h: No such file or directory` — 缺 `libvtk9-qt-dev`。
用 `--disable-GUI`（推荐）。确实要 GUI 再 `sudo apt-get install -y libvtk9-qt-dev` 后重编。

### 4.3 Python 绑定缺失

`openEMS --version` 正常但 `import CSXCAD` 报 `ModuleNotFoundError` — 编译时没加 `--python`。
重跑构建，加 `--python --python-venv-mode venv --python-venv-dir ~/openems-install/venv`。

### 4.4 FEniCSx 装不上

| 报错 | 原因 | 处理 |
|---|---|---|
| `No matching distribution found for fenics-dolfinx` | PyPI 没这个包 | 用 conda-forge |
| `ModuleNotFoundError: petsc4py` | win-64 没有 | 必须装在 WSL/Linux |
| `Can not map ... to a basix type` | `ffcx` 与 `ufl` 版本不配 | 用 conda 一起装，别单独 pip |
| `Microsoft Visual C++ 14.0 is required` | Windows 上 ffcx 要 MSVC | 改用 WSL |

### 4.5 PowerShell 脚本中文乱码

`.ps1` 报 `Unexpected token`、错误信息里中文变乱码 —— Windows PowerShell 5.1 不把无 BOM 的 UTF-8 当 UTF-8。
含中文的 `.ps1` 必须存成 **UTF-8 with BOM**。

### 4.6 openEMS 端口 API

`'ContinuousStructure' object has no attribute 'AddLumpedPort'` —— 端口挂在 **FDTD 对象**上：

```python
port = FDTD.AddLumpedPort(1, 50, start, stop, 'z', 1.0)
```

端口起止点必须**只沿一个坐标轴变化**，否则报 `only a 1D/line integration is allowed`。

### 4.7 GitHub / PyPI 慢或断

- Git：`gh-proxy.com` 镜像 + `insteadOf`
- pip：`-i https://pypi.tuna.tsinghua.edu.cn/simple`
- 大文件：分段并行下载（参考 `work\wsl-pkg\fetch_wsl_parallel.ps1`）

## 5. 换机器必补的几处（v2 新增）

### 5.1 `.venv` 不能跨机器拷贝

从这个目录拷来的 `.venv\Scripts\python.exe` 记的是**旧机器**的绝对路径，新机器上会报
`Fatal error in launcher` 或直接起不来。

到新机器先删掉 `.venv`，重新 `python -m venv .venv` 再装依赖。
同时删掉 `__pycache__`、`.pytest_cache`、`data/results\*` —— 否则验证会读到旧结果，
看起来"跑通了"其实这次根本没算。

**判据**：`data/results/` 里文件的时间戳是这次跑出来的。

### 5.2 磁盘要留 30 GB

实测占用：Ubuntu 基础 ~1.5 GB；openEMS 编译中间产物 3~4 GB；conda 的 fenicsx 环境 4~6 GB；
Windows venv ~1 GB；项目本身 ~1 GB。20 GB 会在编译中途卡住，而编译失败的残局很难收拾。

### 5.3 项目放在 `/mnt/c/...` 下会明显变慢

跨文件系统 I/O 慢，`pytest` 有一部分时间花在磁盘上，这是正常的，不是环境坏了。

两个选择：接受（33 条测试约半分钟到一分钟），或者把项目复制到 `~/ai` 在 WSL 里跑测试。
**别在 `/mnt/c` 上跑 openEMS 的大网格算例**，会慢到没法用。

### 5.4 conda 必须 init 到 bash

`conda create` 装完不等于 `conda activate` 能用：

```bash
~/miniforge3/bin/conda init bash
```

然后重开 shell 或 `source ~/.bashrc`。

**判据**：用 `bash -lc`（会读 `.bashrc`）能 activate 成功；
用 `bash -c` 会出现「明明装好了却找不到 conda」的假象。

### 5.5 WSL 内存要设上限

默认 WSL2 会吃掉宿主相当一部分内存，编译 openEMS 时容易把 Windows 拖死。
在 `C:\Users\<用户名>\.wslconfig` 写：

```ini
[wsl2]
memory=12GB
swap=4GB
processors=8
```

改完 `wsl --shutdown` 再进。**内存小于 16 GB 的机器把 memory 调到 8GB**，并把
`--njobs` 降到 4。

### 5.6 路径长度

Windows 默认 260 字符上限。openEMS 源码树 + 编译产物很容易逼近，
删深层目录时会报「找不到路径的一部分」。

**项目根目录尽量放浅**（例如 `D:\ai`），别放在带中文和空格的路径下。

### 5.7 备份一步，装坏了能回滚

```powershell
wsl --export Ubuntu-22.04 D:\wsl-backup\ubuntu2204.tar
```

回滚：`wsl --unregister Ubuntu-22.04`，再 `wsl --import` 回来。tar 大概 3~6 GB。

装到一半坏掉是常事，这一步只要一分钟。

## 附录 A：dolfinx Poisson 最小验证脚本

放在 `~/poisson_check.py` 跑。判据：峰值 `0.0736 ± 3%`，且网格加密时单调靠近该值
（`-Δu=1`、单位方形、四边 `u=0`，解析峰值约 `0.07367`）。

```python
import numpy as np
from mpi4py import MPI
from dolfinx import fem, mesh, default_scalar_type
from dolfinx.fem.petsc import LinearProblem
import ufl

def solve(n):
    msh = mesh.create_unit_square(MPI.COMM_WORLD, n, n, mesh.CellType.triangle)
    V = fem.functionspace(msh, ("Lagrange", 1))
    u, v = ufl.TrialFunction(V), ufl.TestFunction(V)
    a = ufl.inner(ufl.grad(u), ufl.grad(v)) * ufl.dx
    L = ufl.inner(default_scalar_type(1.0), v) * ufl.dx
    # 边界条件：四边 u=0
    fdim = msh.topology.dim - 1
    facets = mesh.locate_entities_boundary(
        msh, fdim, lambda x: np.isclose(x[0], 0) | np.isclose(x[0], 1)
        | np.isclose(x[1], 0) | np.isclose(x[1], 1))
    dofs = fem.locate_dofs_topological(V, fdim, facets)
    bc = fem.dirichletbc(default_scalar_type(0.0), dofs, V)
    prob = LinearProblem(a, L, bcs=[bc],
                         petsc_options={"ksp_type": "preonly", "pc_type": "lu"})
    uh = prob.solve()
    return float(uh.x.array.max())

for n in (16, 32, 64):
    print(n, solve(n))
```

跑法：

```bash
bash -lc "conda activate fenicsx && python ~/poisson_check.py"
```

预期：三行数字都落在 `0.0736` 附近，且随网格加密从前两个值向 `0.07367` 靠拢。
若第一行就离得很远（比如 0.05 或 0.1），说明求解没收敛或者边界条件没挂上，别往后做。
